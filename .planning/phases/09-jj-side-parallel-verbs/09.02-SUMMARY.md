## Decisions Made

- **`KNOWN_REASONS` declared at module top, not function-adjacent.** TypeScript's TDZ would have made function-adjacent placement runtime-safe (the function is only invoked from outside the module after all top-level declarations complete), but module-top placement matches the precedent at `incomplete-work.ts:24` (`QUEUE_FILENAME`) and reads better for the next maintainer.
- **Captured the conflicted-paths value and used it in the squash-failure error message.** Plan action said "record verbatim". The alternatives — drop the value (wasteful + lint risk) or emit it to a log channel that doesn't exist (premature infrastructure) — both fail the plan's intent. Threading it into the error message is observable on the failure path and zero-cost on the success path.
- **Rule 1 fix on the D-14 gate test was the correct interpretation, not a Rule 4 architectural escalation.** The test's invariant is "gate trips on any non-empty queue", not "gate trips on this specific reason literal". The synthetic `'test-d-14-gate'` was a free-form-string artifact from the pre-plan-01 era and would have failed tsc if test files were included in the tsc surface. Replacing it with a valid literal preserves the test's semantic intent.
- **Final tsc state intentionally has one remaining error.** `backends/jj.ts:1020 — Property 'parallel' is missing` is the documented wave-2 gate for plan 03 (`jj/parallel.ts` sidecar + workspace.parallel adapter wiring) — exactly per the plan's success criteria: "the `incomplete-work.ts:74` error from plan 01 is resolved; remaining errors are exclusively the jj.ts and git.ts `workspace.parallel` gaps closed by plans 03/04."
