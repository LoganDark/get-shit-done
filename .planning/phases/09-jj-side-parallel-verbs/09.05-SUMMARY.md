## Decisions Made

1. **One end-to-end `it` block per N (vs separate dispatch and fanIn `it` blocks).** Originally drafted with dispatch in one `it` and clean fanIn in another. Each describe owns ONE jj repo; re-dispatching in the second `it` collides on jj's `phase-09-subagent-{idx}` workspace-name uniqueness check. The fix: fold the dispatch invariants, the clean fanIn assertions, and the TEST-14 `divergent()` topology check into a single `it` block per N. W2 per-N lifecycle (own beforeAll/afterAll) preserves isolation across N values.
2. **Production-side Rule-1 fixes inside the test plan.** Three plan 03 bugs surfaced during integration. All three were silent-misclassification defects: stale `baseRev` slot heads merging instead of agent work, the WR-04 sentinel firing on clean merges, and an invalid `--no-graph` flag on `jj bookmark list`. None of these could be caught by tsc or the per-file grep gates plan 03 ran in isolation — this plan's test is the first cross-call integration of dispatch+fanIn. Per deviation Rule 1 (auto-fix bugs), all three were rolled into the same commit; SUMMARY documents each fix's rationale.
3. **Per-test 30s timeout (not retry).** Each scenario shells out 6×N jj subprocesses; the default 5s budget overshot for N ∈ {3, 4} on a loaded machine. D-15 / Pitfall 9 forbids `retry: N`; vitest's `{ timeout: 30000 }` option is the approved adjustment knob and remains a deterministic, single-execution measurement.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] parallel.ts: stale `baseRev` slot heads used as fanIn merge targets**
- **Found during:** Task 1, N=2 clean scenario manual repro
- **Issue:** `performJjParallelFanIn` built the N-parent `jj new` argv with `-r <ws.baseRev>` for each workspace. `baseRev` is the dispatch-time slot head — empty by construction. Agent work landed AFTER dispatch (`jj squash -B @ -k -m "..."` inserts a new commit BEFORE `@`); the slot head's change_id never advances. Result: clean fanIn merged empty slots, silently dropping every agent's work.
- **Fix:** Added a pre-step that calls `jj workspace list -T 'json(self) ++ "\n"'`, parses via the SDK-local `parseJjWorkspaceList`, and builds a `name → current-@-change_id` map. The N-parent `jj new` consumes that map for merge parents; the crashed-agent reap branch consumes the same map for its `headChange` entries (deduplicated from a separate workspace-list invocation that was originally in the reap branch).
- **Files modified:** sdk/src/vcs/jj/parallel.ts
- **Commit:** lvwoyrxxnvyl

**2. [Rule 1 - Bug] parallel.ts: `enumerateConflictedPaths` called without `conflicts()` gate**
- **Found during:** Task 1, N=2 clean scenario (after fix #1)
- **Issue:** `enumerateConflictedPaths` documents WR-04: "returns `['<UNRESOLVABLE>']` when `conflicts()` flagged the rev but neither enumeration form yielded paths." The sidecar assumes the caller already gated on `conflicts()`. parallel.ts called it unconditionally and derived `conflicted = paths.length > 0` — so the WR-04 sentinel fired on every clean merge (primary `jj resolve --list` prints nothing; fallback `jj diff --summary` exits 0 with no `C` lines; sentinel returned). `conflicted` was always `true`.
- **Fix:** Two-stage probe: `jj log -r 'conflicts() & <mergeChangeId>' --no-graph` runs first as a boolean gate (mirrors reap.ts's `hasInTreeConflict` at reap.ts:88-101). `enumerateConflictedPaths` is called only if the gate is positive; otherwise `conflictedPaths = []` directly. The sidecar's behavior now matches its documented WR-04 contract.
- **Files modified:** sdk/src/vcs/jj/parallel.ts
- **Commit:** lvwoyrxxnvyl

**3. [Rule 1 - Bug] parallel.ts: `jj bookmark list --no-graph` is invalid**
- **Found during:** Task 1, crashed-worker scenario (after fix #2 unblocked it)
- **Issue:** The post-delete `surplusBookmarks` invariant probe ran `jj bookmark list -T 'name ++ "\n"' --no-graph`. jj 0.41 rejects this: `error: unexpected argument '--no-graph' found`. Unlike `jj log`, the `bookmark list` subcommand has no graph mode to suppress.
- **Fix:** Removed `--no-graph` from the bookmark-list argv. The `jjArgvFlags`-supplied `--quiet` and `--no-pager` remain.
- **Files modified:** sdk/src/vcs/jj/parallel.ts
- **Commit:** lvwoyrxxnvyl
