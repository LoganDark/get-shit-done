<objective>
Implement D-11 (recovery rehearsal). Ship `scripts/dogfood-rehearse.sh` — a standalone script that exercises `scripts/dogfood-restore.sh` (from Plan 03) against a synthetic-dirty clone of THIS repo, BEFORE the real Phase 14 dogfood (Plan 05) runs. Per CONTEXT D-11, the rehearsal is a distinct entry in the Phase 14 PLAN — not a sub-task of the real dogfood — because Pitfall 10 L323's "must work the first time" makes the rehearsal load-bearing.

The script:
1. Creates a sibling-mktemp rehearsal directory (`$REHEARSAL=$(mktemp -d gsd-dogfood-rehearsal-XXXX)`).
2. **Clones THIS repo via `cp -a` (RESEARCH finding #3)** — NOT `git clone`. Rationale: `cp -a` preserves both `.git/` and `.jj/` verbatim and adds zero lint-allowlist entries; `git clone` would require a +1 `scripts/lint-vcs-no-raw-git.allow.json` entry (LINT-05 net diff goes from +1 to +2 — undesirable). `cp -a` is a filesystem-level operation; the clone is not a real upstream-tracked clone, but for rehearsal purposes (exercising `jj op restore` + `tar xf` against a dirty WC), it's equivalent.
3. Captures the rehearsal clone's OWN pre-snapshot (different from the real dogfood's snapshot — this proves `dogfood-restore.sh` is self-contained, not coupled to one specific op-id).
4. Synthesizes dirty state in the clone (modify a tracked file + create a leftover bookmark + `jj squash` to record the dirty state in a new change).
5. Invokes `bash $REPO_ROOT/scripts/dogfood-restore.sh <REH_PRE_OP_ID> <REH_PRE/planning.tar>`.
6. Asserts `jj diff --summary` empty post-restore and the synthetic bookmark is gone.
7. Cleans up the rehearsal dirs via `trap rm -rf` on EXIT.

The plan is `autonomous: false` because Pitfall 10 + D-11 require **human verification** of the rehearsal output before approving the real dogfood. The executor runs the script once; the operator inspects stderr output ("PASS [<assertion>]" lines) and approves the script for production use.

Purpose: Catches edge cases in the `jj op restore` + `tar xf` ordering that would only surface against a real dirty state — exactly the scenario Pitfall 10 is meant to prevent. If the rehearsal fails, the planner has a chance to narrow `dogfood-restore.sh` (e.g., switch to `--what=repo`) BEFORE Plan 05's real dogfood blows up.

Output: One new shell script + one human-verify checkpoint approving the script for production use.
</objective>
