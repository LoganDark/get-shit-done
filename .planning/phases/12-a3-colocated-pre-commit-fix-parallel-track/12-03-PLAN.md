       script the adapter could fire is in scope for re-audit.

       (operation produces the same observable repo state when the hook fires N times as when it
       fires once), `non-idempotent` (repeated firing diverges observable state), `n/a` (no such
       stage script installed). Keep the enum small and closed.

       `| Hook stage | Script path | Operation | Idempotent? | Notes |`. Add one row per

       `git diff --cached --name-only | grep -Eq …` guard and the gated `npm run check:alias-drift`

       `idempotent`. For `.githooks/pre-push`: classify the `GSD_BLOCKED_AUTHOR_REGEX` env guard,
       the `git rev-list` / `git show -s` commit-inspection reads, and the violation-collection +
       `exit 1` path — all are read-only inspections that produce the same accept/reject decision
       on repeated firing, so the verdict is `idempotent`. Cite the relevant line ranges of each
       `.githooks/` script in the Notes column. Do not invent operations the scripts do not
       contain — classify only what is actually present.

    6. Verdict section: state the overall finding. Per D-05's explicit empty-finding requirement,
       if zero non-idempotent operations are found, record that explicitly with a sentence such as
       `No non-idempotent operations found. Baseline recorded for v1.3+ regression — a future
       contributor adding a non-idempotent hook operation must reconcile against this baseline.`
       If any non-idempotent operation IS found, list it and note that the `GSD_HOOK_SKIP_COLOCATED`
       opt-out is the mitigation available to affected users.

    7. Re-runnable verification block: a fenced `bash` block with commands a future maintainer can
       run to re-validate the audit — at minimum, list the `.githooks/` directory contents and
       state the re-fire idempotency probe (e.g. note that running each hook twice in a scratch
       dir leaves identical observable state). The block must be copy-pasteable.

    re-runnable verification block must not instruct a maintainer to run raw `git ` mutations —
    keep it to `ls` / read-only inspection.
