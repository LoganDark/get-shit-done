## Decisions Made

- **`bad ref` (with space) instead of `bad..ref` in jj scenario 3.** The jj-side `validateMainBookmark` regex `/^[A-Za-z0-9._/-]+$/` ACCEPTS consecutive dots (each char individually matches the class). The git-side `validateRefname` is the stricter validator that rejects `..` per `git-check-ref-format(1)`. To deterministically trigger the all-or-nothing throw on the jj validator we use `bad ref` (space is not in the char class). Documented inline with cross-backend rationale.
- **Manifest writer drop chosen over rename.** Per CONTEXT recommendation: the `main_bookmark` field is silent dead-weight on both backends (jj-side already emits `manifest: ''`; the workflow-side reader was retired in Phase 11 P05; no live consumer). Other manifest rows (`worktree_path`, `branch`, `expected_base`) STAY for parity with jj-side state introspection.
- **Legacy CJS shim left as-is (Option A).** `get-shit-done/bin/lib/worktree-safety.cjs:404-421` `reconstructHandleFromLegacyPlan` writes `mainBookmark: entries[0]?.main_bookmark ?? ''` — this is `.cjs` (no TSC check), zero production callers (only 2 legacy tests `wave-cleanup-executor.test.cjs` and `bug-3384-worktree-cleanup-manifest.test.cjs`), so the field write becomes silent dead code at runtime. Minimum-diff principle favored leave-as-is over drop.
- **`validateMainBookmark` helper KEPT** at `jj/parallel.ts:120` — Discretion item per CONTEXT. Same signature, called per-name in the new fan-in pre-validation loop. Delete+re-add would add churn for zero behavioral gain.
- **SC5 git scenario 3 uses `bad..ref` (not `bad ref`)** — `validateRefname` (git-side) explicitly rejects consecutive dots per `git-check-ref-format(1)`, so `bad..ref` is the deterministic throw trigger here.
