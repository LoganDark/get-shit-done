# Phase 14.1: Drop mandatory bookmark on parallel dispatch + fan-in (emergency) - Context

**Gathered:** 2026-05-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Remove the required `mainBookmark: string` field from `ParallelDispatchOpts` / `ParallelDispatchHandle` (single source of truth: `@` (jj) / current HEAD (git), bookmarks advisory). Replace with optional `mainBookmarks?: readonly string[]` (default `[]` → no advance). Fan-in still merges into `@` / current HEAD; only the *advance* step becomes opt-in. Workflow drops the over-broad `current-branch` FATAL preflight so bookmark-less jj `@` and detached-HEAD git become first-class working states. Emergency gap-closure for v1.3 close: the bookmark requirement was baked in by Phase 11 (PARALLEL-01) and Phase 14 should have caught it but didn't surface until a real `--auto` chain hit a bookmark-less `@`.

Requirements: PARALLEL-08. Single plan, single wave.

**STRICTLY out of scope** (locked by D-03 below): `WorkspaceMergeOpts.mainBookmark` at `sdk/src/vcs/types.ts:226` and the matching git `currentBranch !== opts.mainBookmark` guard at `sdk/src/vcs/backends/git.ts:680-687`. Roadmap SC1's ":226" citation is a typo to strike during plan-checker; `vcs.workspace.merge` has zero non-test production callers post-Phase 11 P03 migration; a new MERGE-XX deferred-item REQ-ID is filed in REQUIREMENTS.md so the asymmetry is documented as deliberate.

### D-01: Workflow touch scope is SYMMETRIC (both files + CR-03 lint)

Both `get-shit-done/workflows/execute-phase.md` AND `get-shit-done/workflows/quick.md` drop the `current-branch` FATAL preflight. The Phase 11-08 CR-03 lint at `tests/quick-md-parallel-dispatch.test.cjs:87-94` is updated in lockstep so the lint assertion stays meaningful (it currently asserts the preflight is present in BOTH files; after this phase it asserts the preflight is ABSENT in both).

### D-02: CLI flag shape is REPEATED SINGULAR `--main-bookmark`

The `sdk/src/query/workspace-parallel-dispatch.ts` bridge keeps the singular `--main-bookmark <name>` flag token; accumulates repeats into the `mainBookmarks: readonly string[]` array. No flag → empty list → bookmark-less first-class. The `main_bookmark_required` reason envelope path is simply deleted (not mutated) — every other reason token stays stable.

- **Parser edit** is one-line: `mainBookmark = args[++i]` → `mainBookmarks.push(args[++i])`. No de-dup; preserve order. Refnames forbid both whitespace and commas, so no future delimiter clash.
- **Idiom precedent:** `gh pr create --label foo --label bar`, `git -c k=v -c k=v`, `ssh -o k=v -o k=v`. The user is the sole consumer (private fork); zero out-of-tree callers to break.
- **Fan-in CLI bridge** (`sdk/src/query/workspace-parallel-fan-in.ts`) is unaffected — it has no `--main-bookmark` flag; it reads the bookmark list from the Handle JSON. Dispatch is the only CLI multiplicity surface.

1. **Empty-list dispatch+fan-in** on bookmark-less jj `@` (no `jj bookmark create` setup; orchestrator on anonymous change) AND on detached-HEAD git (`git checkout --detach HEAD`). With the field removed from the Handle, the planner's choice: drop the field entirely from the manifest, or convert to `main_bookmarks: mainBookmarks` array. **Recommendation: drop the field entirely.** The jj-side already emits `manifest: ''` (Phase 11 D-01 sidecar retirement); the workflow-side reader was retired in Phase 11 P05 (`WAVE_WORKTREE_MANIFEST` eliminated per D-01); no live consumer reads the `main_bookmark` field on either backend. Net: the manifest writer on git keeps writing other fields (`worktree_path`, `branch`, `expected_base`) for parity with jj-side state introspection, but the `main_bookmark` row drops.
