<objective>
Rewire `get-shit-done/workflows/execute-phase.md` so the parallel-dispatch + fan-in logic routes through the new cross-backend `vcs.workspace.parallel.*` SDK verbs (shipped Plan 11.2) instead of inline raw-git shell. Per D-01, no on-disk manifest file is involved — the orchestrator captures the dispatch Handle JSON in a shell variable, iterates `.workspaces[]` to spawn Agent() calls, accumulates results into a JSON array, and pipes that to `gsd-sdk query workspace.parallel.fan-in` via stdin. Per Pitfall 5 + D-07, the sequential one-Agent-per-message `run_in_background: true` dispatch pattern is preserved verbatim — the surrounding boilerplate (manifest mktemp, raw-git worktree-add, cleanup-tail block) is what disappears, not the Agent() loop itself. Per D-07, `maxConcurrency` is passed as `undefined` (PARALLEL-06 is honored at the field-level on the adapter contract; workflow exposure is deferred to Phase 14 dogfood metrics). The `<worktree_branch_check>` orchestrator-side templating block is deleted — the agent-side replacement lives in `gsd-executor.md` per Plan 11.4. The `<execution_context>` load of `worktree-path-safety.md` is replaced with `dispatch-cwd-safety.md`. Orchestrator rules and stall-surveillance probes survive untouched.

Purpose: Delete ~290 LOC of inline raw-git from a workflow file — the user-observable architectural evidence that the cross-backend parallel-verb surface works end-to-end. After this plan ships, the only consumer left to migrate is `quick.md` (Plan 11.6).
