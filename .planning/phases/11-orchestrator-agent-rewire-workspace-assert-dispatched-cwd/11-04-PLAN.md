<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Orchestrator → Agent() invocation | The orchestrator passes a `cwd` to each subagent's Agent() invocation. The new replacement guard block validates the cwd via `workspace.assert-dispatched-cwd` before any commit work. The cwd parameter is the only orchestrator-injected input to the verb. |
| Agent prompt → gsd-sdk subprocess | The agent shell pipes `DISPATCH_CHECK=$(gsd-sdk query workspace.assert-dispatched-cwd --cwd .)` — the `.` cwd is literal, not orchestrator-controlled. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.04-01 | Injection | Orchestrator-injected `cwd` parameter via Agent() invocation | mitigate | The `workspace.assert-dispatched-cwd` verb itself takes `--cwd <path>` and the agent shell hard-codes `--cwd .` (the agent's current directory, established when Agent() was spawned). The orchestrator controls the spawn cwd, not a runtime --cwd flag. There is no command-injection path here — the literal `.` is fixed in the prompt text. Even if a malicious orchestrator passed a hostile spawn cwd, `vcsExec` (called downstream by the adapter) uses array-form argv with no shell interpolation. |
| T-11.04-02 | Tampering | Replacement guard block in `<task_commit_protocol>` | mitigate | The block reads `OK`, `IS_PRIMARY`, `WS_NAME` via `jq -r` — `jq -r` strips quotes but does not execute anything. Even a malicious adapter return value (e.g. `workspaceName: ";rm -rf /;"`) only flows into `echo` for diagnostic output — never into `eval` or backticks. |
| T-11.04-03 | Repudiation | D-06 deletion check (preserved untouched) | accept | The post-commit DELETIONS check at lines 527-537 is the load-bearing #3091 defense per CONTEXT.md D-06. Plan 11.3 retires the orchestrator-side `deletions_detected` pre-check; this agent-side check is the relocation target. Test coverage exists (`bug-3091-merge-deletes-files.test.cjs` if present) for this defense. |
| T-11.04-04 | Documentation drift | Renamed reference file in workflow `<execution_context>` loads | mitigate | All in-repo referrers updated per Task 2 step 3; the regression test at `bug-3097-3099-executor-worktree-path-safety.test.cjs` is flipped to assert the new name + verb literal — catches broken references at CI time. |
| T-11.04-05 | Performance / Latency (informational) | Per-agent subprocess invocation of `gsd-sdk query workspace.assert-dispatched-cwd` | accept | Each Agent() invocation spawns one subprocess for the dispatch sanity check (D-03 minimal predicate is acceptable per CONTEXT). Subprocess latency adds ~50-200ms per agent dispatch — noted as a Phase 14 dogfood-metrics watch item in case wave-of-N agents amortizes badly at high N. NOT BLOCKING — annotation only; no mitigation needed unless dogfood metrics surface a real bottleneck. |
</threat_model>
