## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI → SDK handler | The orchestrator (or any caller) passes `--cwd <path>` and `--plan`/`--handle`/`--results` JSON via stdin or `@file`. The handler treats these as untrusted-shaped data even though the orchestrator is trusted. |
| Adapter → subprocess | `createVcsAdapter` + `vcs.workspace.list()` / `vcs.workspace.parallel.dispatch` / `vcs.workspace.parallel.fanIn` call `vcsExec` which spawns `git` or `jj`. Argv assembly is the historical injection vector. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.02-01 | Tampering / Injection | `--cwd <path>` flag on all 3 handlers | mitigate | Path is passed verbatim to `createVcsAdapter(cwd)` which uses it as working directory for `vcsExec`. `vcsExec` uses array-form argv (no shell), so a malicious cwd cannot inject command tokens. Path traversal is bounded by what the calling shell would allow access to anyway (the orchestrator process already trusts itself). No additional validation required beyond what `head-ref.ts` already accepts as the precedent. |
