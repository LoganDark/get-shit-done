<objective>
Close the Phase 18 UAT blocker gap (test 5): the `assert_clean_wc` gate fences key
dirty-detection on `status --porcelain` envelope field `.raw` being non-empty. On the
git backend porcelain `.raw` is empty when clean, but the jj backend's `status()`
(src/vcs/backends/jj.cts:429-441) always returns `raw = jj st stdout` — human-readable
text ("The working copy has no changes.\nWorking copy (@)...") that is non-empty even
on a clean working copy. Result: every clean-WC gate check on a jj repo false-positives
into `FATAL: working copy is dirty` exit 1, blocking ALL transitions and phase
completions (live-reproduced on this repo, vcs.adapter jj).

Fix: key the DIRTY predicate on the structured `entries` array (`[.entries[].path]` —
empty = clean; this is the cross-backend porcelain contract), preserving every
fail-closed branch. `.raw` is never a cleanliness predicate.

Scope note (discovered during gap planning, same defect class, same fix shape):
- The UAT gap names two fences (transition.md ~line 434, execute-phase.md ~line 1691).
  A THIRD byte-similar fence exists in `gsd-core/workflows/plan-phase.md` §16 (~line
  1781) — produced by the same Phase 18 REVIEW WR-01/WR-02 rewrite pass, carrying the
  identical `.raw`-keyed predicate, live on jj at the end of every /gsd-plan-phase run.
  It is fixed here too; leaving it would keep the diagnosed truth ("gate passes on a
  clean WC on BOTH backends") false for one of the three gate sites.
- `gsd-core/workflows/undo.md` execute_revert step (~line 215) keys its dirty-tree
  guard on the same `.raw // ""` non-empty test — on jj it ALWAYS reads dirty, making
  /gsd-undo unusable on a jj repo. Same one-line predicate swap, included here.

jq semantics making this fail-closed AND clean-silent: `join` on an empty array emits
`""`, which is truthy under `jq -e` (exit 0) and empty under `$(...)` capture → clean
path falls through silently. Non-empty entries → newline-joined paths → the FATAL
branch fires. `.ok != true`, `.entries` absent or non-array → `error(...)` → jq exits
non-zero → the second FATAL fires. Unparseable JSON → jq parse error → same.

The old `DIRTY=` line, the `if [ -n "$DIRTY" ]` test, the two `# Prefer structured
... fall back` comment lines, the `DIRTY_PATHS=$(... [.entries[]?.path] ...)` recompute,
and the `[ -n "$DIRTY_PATHS" ] || DIRTY_PATHS="$DIRTY"` raw fallback are all REMOVED —
entries are now authoritative, so the "entries empty but probe says dirty" fallback
branch is unreachable by construction (UAT gap missing-item 2: drop the fallback).
