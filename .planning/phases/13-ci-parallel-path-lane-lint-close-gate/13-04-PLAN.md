  `group: parallel-e2e-${{ github.workflow }}-${{ github.head_ref ||
  github.run_id }}`, `cancel-in-progress: true`.

JOB `parallel-e2e` (matrix, INVERTED polarity vs test.yml):
  `runs-on: ubuntu-latest`, `timeout-minutes: 15`.
  `continue-on-error: ${{ matrix.backend == 'git' }}` — the INVERSE of
  test.yml (there git is required, jj allow-fail). D-03's whole rationale.
  `strategy: { fail-fast: false, matrix: { backend: [git, jj-colocated] } }`.
  Steps:
    1. `actions/checkout` — SHA-pinned verbatim from test.yml, `fetch-depth: 0`.
    2. `actions/setup-node` — SHA-pinned verbatim from test.yml,
       `node-version: 24`, `cache: 'npm'`.
    3. Install jj — `if: matrix.backend == 'jj-colocated'`; copy the
       `v0.41.0` tarball-curl block from test.yml VERBATIM (drop `jj-native`
       from the `if:`).
    4. `npm ci`.
    5. `npm run build:sdk` — REQUIRED before the harness (the harness depends
       on `sdk/dist/cli.js`).
    6. Run the harness — `shell: bash`, `env: { GSD_E2E_BACKEND: ${{
       matrix.backend }}, GSD_SDK: "node $GITHUB_WORKSPACE/sdk/dist/cli.js" }`,
       `run: bash scripts/e2e-parallel-phase.sh`. (Set `GSD_SDK` so the harness
       uses the repo-checkout SDK, not a global install — RESEARCH Pattern 4.)
    7. CI-06 audit step — `shell: bash`, `run: node
       scripts/audit-workflow-raw-git.cjs`. A non-zero exit (raw-git
       regression beyond the frozen 127-hit baseline) fails the cell.
  Every `run:` step declares `shell: bash`; multi-line `run:` blocks open with
  `set -euo pipefail`.

JOB `parallel-e2e-gate` (D-04 option b — the RECOMMENDED blocking guarantee):
  `runs-on: ubuntu-latest`, `needs: [parallel-e2e]`, `if: always()` (runs even
  when the matrix job's overall conclusion is failure).
  One step: inspect `needs.parallel-e2e.result` (the aggregate of all matrix
  cells). Because the git cell carries `continue-on-error: true`, a failed git
  cell does NOT flip the aggregate to `failure` — but a failed jj-colocated
  cell (no `continue-on-error`) DOES. So requiring `aggregate == 'success'` is
  exactly "the jj-colocated cell passed". If the aggregate is not `success`,
  emit `::error::` and `exit 1`.
  RESEARCH §"Pattern 3" supplies the complete skeleton.

  A2 RED-CELL CONFIRMATION (RESEARCH Assumption A2, MEDIUM-confidence): the
  aggregate semantics above are the documented GitHub model but the exact
  interaction of per-cell `continue-on-error` with the job-level aggregate
  `result` should be confirmed. The executor adds ONE deliberate temporary
  red-cell check during implementation (locally simulate or reason through:
  if the git cell fails, does `parallel-e2e-gate` still pass? if the
  jj-colocated cell fails, does it fail?). If the aggregate proves
  unreliable, fall back to explicit per-cell `outputs:` + `fromJSON` that the
  gate job reads — RESEARCH names this fallback. Do NOT leave the red-cell
  check in the committed workflow; it is an implementation-time verification
  only.

BRANCH-PROTECTION REGISTRATION: `parallel-e2e-gate` is the job-name string the
user must add to GitHub branch-protection required checks. This is config
OUTSIDE the repo — Phase 13 cannot set it. The SUMMARY must flag this for the
user at ship time (D-04 / RESEARCH Runtime State Inventory).
