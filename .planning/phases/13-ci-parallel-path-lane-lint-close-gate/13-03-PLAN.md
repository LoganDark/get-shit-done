<verb_contract>
<!-- Verified against the live tree 2026-05-22 (RESEARCH.md §"Verified Verb
     Surface"). The harness must match these exactly. -->

CANONICAL VERB NAMES (note the hyphen on fan-in):
  - `workspace.parallel.dispatch`
  - `workspace.parallel.fan-in`   (CLI is hyphenated; the TS method is fanIn)

`gsd-sdk` INVOCATION IN CI: after `npm run build:sdk`, `node
$GITHUB_WORKSPACE/sdk/dist/cli.js <args>` is the exact equivalent of `gsd-sdk
<args>` (the `bin/gsd-sdk.js` shim is `spawnSync(node, [sdk/dist/cli.js,
...args])`). The harness MUST accept the invocation via an env var (e.g.
`GSD_SDK`, defaulting to `gsd-sdk` when unset) so it works both in CI (repo
checkout) and when GSD is globally installed.

dispatch CONTRACT (`workspace-parallel-dispatch.ts`):
  flags: `--cwd <path>` (default projectDir), `--phase <number>` REQUIRED,
  `--main-bookmark <name>` REQUIRED, `--plan <input>` REQUIRED,
  `--max-concurrency <n>` optional (omit it).
  `--plan` resolution: `@-` = stdin, `@<path>` = file, else inline JSON.
  `--plan` JSON shape: `Array<{ agentId: string; planId: string;
  workspacePath?: string }>`.
  Success returns a FLAT envelope: the Handle JSON directly, `.ok` absent.
  Failure returns `{ ok: false, reason: '<code>' }`.

fan-in CONTRACT (`workspace-parallel-fan-in.ts`):
  flags: `--cwd <path>`, `--handle <input>` REQUIRED, `--results <input>`.
  Both `--handle` and `--results` accept `@-` (stdin) or `@<path>` (file);
  INLINE JSON IS REJECTED for both.
  CRITICAL: both inputs cannot simultaneously be stdin — `--handle @-
  --results @-` is rejected with `reason:
  'handle_and_results_cannot_both_be_stdin'`. The harness MUST write the
  Handle JSON to a `mktemp` file and pass `--handle "@$HANDLE_FILE" --results
  @-`, then `rm -f` the file (exactly what `execute-phase.md` does).
  `--results` JSON shape: `Array<{ agentId, exitCode, lastChangeId?,
  stderr? }>`.

ParallelDispatchHandle shape: `{ phaseRoot, phaseNumber, mainBookmark,
manifest, workspaces: [{ name, path, baseRev, agentId }] }`. Frozen pure JSON.
  manifest: git → truthy abs path; jj → '' (empty string, Phase 11 D-01
  retired the jj-side manifest).

FanInResult shape: `{ merged, conflicted, conflictedPaths, incompleteQueued,
failedReaped, surplusBookmarks }`.
  Clean fan-in merged.length: git → N (one per 2-parent merge) = 2 for the
  synthetic 2-plan phase; jj → 1 (one N-parent octopus merge).
</verb_contract>

<harness_sequence>
<!-- The 1:1 mirror of execute-phase.md. Reproduce this sequence. -->

DISPATCH (mirror execute-phase.md dispatch block):
  Build the 2-plan JSON. With two agent labels (e.g. `e2e-a e2e-b`):
    PLANS_JSON=$(printf '%s\n' $AGENT_LABELS | jq -R . | jq -sc 'map({agentId: ., planId: .})')
  Pipe it to dispatch:
    HANDLE_JSON=$(printf '%s' "$PLANS_JSON" \
      | $GSD_SDK query workspace.parallel.dispatch \
          --cwd "$REPO" --phase 13 --main-bookmark "$MAIN_BOOKMARK" --plan @-)
  Guard empty + failure envelope:
    [ -z "$HANDLE_JSON" ] && { echo "FATAL: dispatch returned empty Handle" >&2; exit 1; }
    HANDLE_OK=$(printf '%s' "$HANDLE_JSON" | jq -r '.ok // "true"')
    [ "$HANDLE_OK" = "false" ] && { echo "FATAL: dispatch failed: $HANDLE_JSON" >&2; exit 1; }

FAN-IN (mirror execute-phase.md fan-in block — the mktemp Handle-file dance is
mandatory):
    HANDLE_FILE=$(mktemp "${TMPDIR:-/tmp}/gsd-handle-XXXXXX.json")
    printf '%s' "$HANDLE_JSON" > "$HANDLE_FILE"
    FAN_RESULT=$(printf '%s' "$RESULTS_ACCUM" \
      | $GSD_SDK query workspace.parallel.fan-in --cwd "$REPO" --handle "@$HANDLE_FILE" --results @-)
    rm -f "$HANDLE_FILE"

`RESULTS_ACCUM` is a `ParallelAgentResult[]` JSON array — one entry per agent,
each `{agentId, exitCode: 0}` (the lastChangeId/stderr fields are optional).
Build it after the per-workspace commits in step 5.
</harness_sequence>
