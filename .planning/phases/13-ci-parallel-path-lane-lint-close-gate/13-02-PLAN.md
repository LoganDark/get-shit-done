<baseline_design>
<!-- D-09 / phase-scope-decision: the baseline is a PER-FILE count map, not a
     bare total. A per-file map is the robust form — a bare total of 127 lets a
     removal in one file mask an addition in another. The per-file map detects
     a regression in any single file even if the global total is unchanged. -->

BASELINE GRANULARITY: per-file. The frozen baseline is the
`<verified_baseline>` object above, embedded as an `Object.freeze`d constant in
the `.cjs` source (the `migr-06-close-gate.cjs` embedded-constant precedent).
An embedded constant in committed source — or a committed companion baseline
file under `scripts/` — does NOT violate CONTEXT.md D-06: D-06 forbids the
audit WRITING transient output into the working tree AT RUNTIME; a static,
intentionally-version-controlled baseline is source, not runtime output. The
executor choice: embedded `const` (recommended — single file, matches
`migr-06-close-gate.cjs`) OR a committed
`scripts/audit-workflow-raw-git.baseline.json` the script `require`s. Either
is acceptable; embedded `const` is simpler.

REGRESSION RULE (per-file): for each scanned file, compare the current raw-git
count against the baseline count for that path (a path absent from the
baseline is treated as baseline 0).
  - current count > baseline count for that path  → REGRESSION (a file got
    NEW raw-git, or a new file with raw-git appeared)
  - current count <= baseline count, OR the file dropped to 0, OR the file
    disappeared  → OK (raw-git removed is never a regression)
`result.ok` is `true` iff there are zero regressions. `result.regressions` is
an array of `{ path, baseline, current }` for the per-file diagnostic the CLI
prints on a non-zero exit (mirrors `check-skip-count.cjs` per-file diagnostic).

EXIT CODE: `process.exit(result.ok ? 0 : 1)` inside the `require.main` block.
The audit IS the CI-06 gate. `audit-id-namespace.cjs` never exits — adding the
exit code is the deliberate divergence the pattern map flagged.
</baseline_design>
